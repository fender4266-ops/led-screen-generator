## 🎯 О проекте

**LED Multi-Screen Map** решает две задачи AV-инженера:

| Задача | Решение |
|---|---|
| 🎨 Нужна **тестовая картинка** под конкретный экран | Генератор шахматки/градиента с крестом, текстом и логотипами |
| ⚙️ Нужен **расчёт железа** под экран | Подбор процессора, карта расключения, электрика, риггинг |

Всё в **одном файле `index.html`** — можно кинуть в мессенджер, положить на флешку, открыть на площадке без интернета.

## 🎨 Страница 1: Визуализация

Генератор тестовых/калибровочных изображений для LED-экранов.

### Мультиэкранная композиция

- ➕ **Неограниченное количество экранов** — вкладки сверху
- 👁️ **Скрытие экрана** — клик по глазу на вкладке (не попадёт в PNG)
- 📋 **Дублирование** — копия со всеми настройками и логотипами
- 🖱️ **Drag & Drop** — таскай экраны мышью прямо по превью
- 🧲 **Магнитное прилипание** — края экранов «липнут» друг к другу (порог 40 px)
- ⇧ **Shift при перетаскивании** — привязка к сетке 10 px
- ↔️ **Авто-раскладка** — выстроить все экраны в ряд или в столбец

### Способы задания размера

| Режим | Что вводишь | Что получаешь |
|---|---|---|
| **По кабинетам** | Ширина/высота в метрах + размер и разрешение кабинета | Разрешение считается автоматически |
| **Прямой ввод** | Разрешение в пикселях | Пресеты HD / Full HD / 2K / 4K / 5K / 8K одним кликом |

### Отрисовка

- 🏁 **Шахматка** — два цвета, клетка = кабинет
- 🌈 **Градиент** — горизонтальный / вертикальный / диагональный
- ✖️ **Крест + круг** — геометрия для проверки геометрических искажений
- 🔤 **Текст по центру** — название, разрешение, физический размер
  - Размер шрифта задаётся в **% от максимума, влезающего в круг** — текст никогда не вылезет
  - Полупрозрачная подложка с настраиваемым цветом
- 🖼️ **Два логотипа**
  - **Лого 1** — по центру над текстом, с ручным позиционированием X/Y
  - **Лого 2** — в любом из четырёх углов
  - Прозрачность, размер в % от ширины, подложка со скруглением

### Оверлеи (отладочные слои)

| Слой | Назначение |
|---|---|
| ▦ Линии сетки | Границы кабинетов |
| 🔢 Номера | Порядковый номер каждого кабинета |
| 🔲 Границы экранов | Рамка + подпись с названием и разрешением |

**Порядок слоёв фиксирован:** фон → сетка → номера → **текст и лого сверху** → рамки → подписи.
Так надписи никогда не перекрываются номерами кабинетов.

### Пресеты цветов

- 6 заводских пресетов (Ч/Б, Ч/Оранж, Зел/Красн, Син/Фиол, Циан/Роз, Жёлт/Фиол)
- ➕ Сохранение своих пресетов в `localStorage`
- 🖱️ **ПКМ по пресету** — удалить
- 🌐 Применить текущие цвета сразу ко всем экранам
- 🎲 Случайный пресет
- 🔄 Авто-ротация: каждый новый экран получает следующий пресет

### Превью

- 🔍 **Зум ± 25%** (диапазон 5 %…500 %) + сброс на авто-вписывание
- 📌 **Закрепление сверху** — превью «прилипает» к верху окна и остаётся видимым при скролле настроек
- 🎯 Активный экран подсвечивается бирюзовой рамкой

## ⚙️ Страница 2: Инженерный расчёт

### Ввод параметров

- 4 типа кабинета одним кликом: **P3.9 / P2.9 / P2.6 / P1.9**
- Двусторонний пересчёт: **метры ⇄ количество кабинетов**
- 🔄 Авто-синхронизация со страницей визуализации при переключении вкладок

### Разводка портов (8 направлений)

Иконки в стиле **NovaLCT** — каждая рисуется программно как реальная траектория змейки со стрелкой направления и красной точкой старта.

```
Вертикальные (колонны):  dir 1, 3, 5, 7
Горизонтальные (строки): dir 2, 4, 6, 8
```

**Ключевое правило:** колонна (или строка) **не рвётся между портами**, если целиком влезает в лимит кабинетов на линию. Алгоритм группирует целые колонны в одну линию, а рвёт только вынужденно.

### ⬛ Режим прямоугольных зон

Альтернативный алгоритм — жадная нарезка поля на **прямоугольные зоны**, максимально близкие к квадрату:

1. Идём по свободным клеткам слева-направо, сверху-вниз
2. Для каждой находим **максимальный прямоугольник** площадью ≤ лимита линии, с минимальной разницей сторон
3. Помечаем занятым, переходим дальше

Результат: `⬛ Зоны: 4×4 ×12 + 4×2 ×3 | Всего портов: 15`

Удобно, когда нужны компактные зоны вместо длинных змеек.

### Выбор процессора

| Режим | Поведение |
|---|---|
| 🤖 **Авто** | Подбирает самый компактный процессор, который тянет экран в 1 шт |
| 👤 **Вручную** | Выбираешь модель — считается, **сколько штук** нужно |

Выпадающий список расположен **прямо в блоке результата**, рядом с итогом.

**Важное правило:** доступна только **половина портов** (`master = ports / 2`), вторая половина — резерв (backup).

### 🗺️ Карта расключения

- Цветная сетка: каждый порт — свой цвет (20 цветов в палитре)
- Номер кабинета внутри линии на каждой клетке
- Путь кабеля со стрелкой направления
- Белый кружок в точке старта линии с меткой:
  - `P1`, `P2`… — если процессор один
  - `1.3`, `2.1`… — формат **`процессор.порт`**, если процессоров несколько
- 📄 Опциональная панель внизу: процессор + мощность + вес

## 🧮 Формулы расчётов

### Мощность

```
Пиковая        = кабинетов × Вт/кабинет
Средняя        = Пиковая × 0.35            # обычный контент
Вт на м²       = Пиковая / площадь
Ток 1 фаза     = Пиковая / 220
Ток 3 фазы     = Пиковая / (220 × 3)       # на фазу
Автомат        = ceil(ток × 1.25 / 5) × 5  # округление до 5 А
```

### Вес и подвес

```
Чистый вес     = кабинетов × кг/кабинет
Вес в сборе    = Чистый × (1 + коммутация%)
Расчётный      = В сборе × (1 + запас%)
Лебёдок        = ceil(Расчётный / грузоподъёмность)
На лебёдку     = В сборе / количество лебёдок
```

Цветовая индикация загрузки лебёдки: 🟢 ≤ 75 % · 🟡 76–90 % · 🔴 > 90 %

### Количество процессоров

```
master         = ports / 2
needCount      = max(
                   ceil(всего пикселей / макс. пикселей),
                   ceil(линий / master)
                 )
```

## 💾 Сохранение состояния

Приложение различает **обновление страницы** и **новое открытие вкладки** через `sessionStorage`:

- 🔄 **F5** → состояние восстанавливается (экраны, логотипы, инженерные настройки)
- 🆕 **Новая вкладка** → чистый старт

### Ключи хранилища

| Ключ | Где | Что хранит |
|---|---|---|
| `ledSession` | localStorage | Экраны, позиции, поля, логотипы (dataURL) |
| `ledEngSession` | localStorage | Настройки инженерной страницы |
| `ledPresets` | localStorage | Пользовательские пресеты цветов |
| `pinPreview` | localStorage | Закреплено ли превью |
| `collapse_*` | localStorage | Свёрнутые панели |
| `ledAlive` | sessionStorage | Флаг «вкладка жива» для детекта F5 |

> ⚠️ Логотипы хранятся как base64-dataURL. При больших изображениях можно упереться в лимит `localStorage` (~5–10 МБ) — сессия просто не сохранится, приложение продолжит работать.

## 🏗️ Архитектура кода

Один файл, ~2600 строк. Логические зоны:

```
index.html
├── <style>                       Тёмная тема + адаптив (820 px / 480 px)
├── <body>
│   ├── .page-switch              Переключатель страниц
│   ├── #page-visual              Страница визуализации
│   └── #page-engineer            Страница инженера
└── <script>
    ├── МОДЕЛЬ ДАННЫХ
    │   ├── FIELD_IDS[]           Список полей формы для сериализации
    │   ├── defaultScreen()       Фабрика объекта экрана
    │   └── screens[] / activeId  Состояние приложения
    │
    ├── ФОРМА ⇄ ОБЪЕКТ
    │   ├── readFormToScreen()    DOM → объект
    │   └── writeScreenToForm()   Объект → DOM
    │
    ├── ОТРИСОВКА (Canvas 2D)
    │   ├── drawScreenBackground()  Слой 1: шахматка / градиент
    │   ├── drawScreenForeground()  Слой 3: крест + лого + текст
    │   ├── drawCenterBlock()       Авто-подбор размера шрифта
    │   ├── drawLogo2()             Лого в углу
    │   └── drawComposition()       Мультипроходный рендер со слоями
    │
    ├── ЭКСПОРТ
    │   ├── savePNG()             Общий PNG
    │   └── saveAllPNG()          Пакет отдельных PNG
    │
    ├── ВЗАИМОДЕЙСТВИЕ
    │   ├── enableDrag()          IIFE: перетаскивание + магниты
    │   ├── zoomPreview()         Зум превью
    │   └── togglePinPreview()    Закрепление превью
    │
    ├── СПРАВОЧНИКИ
    │   ├── CAB_TYPES{}           Кабинеты
    │   ├── PROCESSORS[]          Процессоры
    │   └── PORT_COLORS[]         Палитра портов
    │
    ├── АЛГОРИТМЫ РАЗВОДКИ
    │   ├── buildSnake()          Змейка по 8 направлениям
    │   ├── buildRectSnake()      Прямоугольные зоны
    │   ├── findRectTiling()      Жадная нарезка
    │   └── bestZoneForArea()     Поиск оптимального прямоугольника
    │
    ├── РАСЧЁТЫ
    │   ├── engCalc()             Главный расчёт + вывод
    │   ├── buildProcSpecCard()   HTML-карточка процессора
    │   ├── buildPowerCard()      HTML-карточка мощности
    │   └── buildWeightCard()     HTML-карточка веса
    │
    ├── КАРТА
    │   ├── engDrawMap()          Карта расключения
    │   └── drawMapSpecs()        Панель спеки на карте
    │
    └── СПЕЦИФИКАЦИЯ
        ├── engBuildSpecsData()   Чистый калькулятор (без рендера)
        └── engSaveSpecsPNG()     Рендер + скачивание
```

### Принципы

**1. Разделение «калькулятор / рендерер»**
`engBuildSpecsData()` только считает и возвращает объект с числами. `engSaveSpecsPNG()` только рисует. Захочешь PDF или Excel — калькулятор переиспользуется как есть.

**2. Мультипроходный рендер**
`drawComposition()` рисует не «экран за экраном», а «слой за слоем» по всем экранам сразу. Иначе фон соседнего экрана затирал бы оверлеи предыдущего.

**3. Данные отдельно от логики**
`CAB_TYPES` и `PROCESSORS` — обычные объекты вверху скрипта. Добавление модели не требует правки алгоритмов.

**4. Единый источник масштаба**
Canvas всегда в реальном разрешении, масштабируется только через CSS. Функция `getScale()` вычисляет коэффициент на лету, поэтому зум и перетаскивание не конфликтуют.

## 🔧 Как добавить своё оборудование

### Новый тип кабинета

```javascript
const CAB_TYPES = {
  // ...существующие
  'P4.8': { px: 104, perLine: 50, weight: 7.5, power: 130 }
};
```

Затем добавь кнопку в HTML:

```html
<button class="cabtype-btn" data-cab="P4.8" onclick="engSetCab('P4.8')">P4.8 · 104×104</button>
```

### Новый процессор

```javascript
const PROCESSORS = [
  // ...существующие, порядок = от слабого к мощному
  {
    name: 'Colorlight Z6',
    maxPx: 5200000,
    ports: 8,
    pxPerPort: 650000,
    maxInput: '3840×2160 @60Hz',
    hdmiSync: false,
    video: 'HDMI 2.0, DVI',
    audio: true,
    redundancy: 'Hot backup',
    note: '8 портов'
  }
];
```

> ⚠️ Массив должен быть отсортирован **по возрастанию мощности** — авто-подбор берёт первый подходящий.

### Своя палитра портов

```javascript
const PORT_COLORS = ['#ff0000', '#00ff00', /* ... */];
```

## ⚠️ Ограничения

- Физический размер кабинета жёстко **0.5 × 0.5 м** на инженерной странице
- Перетаскивание экранов — только мышью (без touch-событий)
- Пакетное скачивание отдельных PNG может блокироваться браузером — разреши множественные загрузки для сайта
- Очень большие композиции (> 20 000 px по стороне) могут упереться в лимит Canvas в браузере
- Опция «Каждый порт заходит с одного края» присутствует в UI, но пока не влияет на алгоритм разводки

## 🤝 Вклад в проект

Проект — один HTML-файл, поэтому всё просто:

1. Форкни репозиторий
2. Создай ветку: `git checkout -b feature/my-feature`
3. Внеси правки в `index.html`
4. Проверь в браузере (обе страницы, экспорт PNG, F5-восстановление)
5. Коммит: `git commit -m 'feat: краткое описание'`
6. Пуш и Pull Request

**Стиль кода:** сохраняй существующее оформление — блоки-разделители `─── Название ───`, комментарии на русском, эмодзи в заголовках секций.

## 💡 Дисклеймер

Расчёты носят **справочный характер** и основаны на типовых значениях.
Перед реальным монтажом **сверяйся с паспортами конкретного оборудования** и требованиями площадки.
Особенно это касается риггинга: коэффициенты запаса и грузоподъёмность точек подвеса должен подтвердить ответственный за такелаж.
